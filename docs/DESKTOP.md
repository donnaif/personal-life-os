# DESKTOP — تطبيق سطح المكتب (`apps/desktop`)

غلاف Electron يعرض واجهة `apps/web` المبنية داخل نافذة Windows أصلية، ويتصل بالـAPI المحلي.
لا يحتوي نسخة من كود الواجهة: يقدّم الملفات المبنية + وكيل `/api`.

---

## 1. الأوامر

| الأمر | ما يفعله |
| --- | --- |
| `npm run build:web` | يبني `apps/web/dist` (مطلوب قبل الحزم). |
| `npm run build:desktop` | يبني `apps/desktop/dist` (TypeScript → CommonJS). |
| `npm run dev:desktop` | يشغّل Electron في وضع التطوير (`--dev`) مقابل Vite على 3101. |
| `npm run smoke:desktop` | يشغّل التطبيق، ينفّذ 17 خطوة تحقّق، يخرج بالرمز 0/1. |
| `npm run package:win` | يبني ويحزم إلى `apps/desktop/release/Personal Life OS-win32-x64/`. |

المتطلبات: الـAPI يعمل على `127.0.0.1:3100` (يُشغَّل من `apps/api`).

## 2. مسار التشغيل الداخلي

```
النافذة (renderer) ──► http://127.0.0.1:3105   (خادم محلي داخل العملية الرئيسية)
                          ├── /            → apps/web/dist (SPA fallback)
                          └── /api/*       → http://127.0.0.1:3100/*  (تُحذف البادئة)
بروتوكول IPC (preload + contextBridge) ──► قائمة، tray، إعدادات، إشعارات، تشفير، مخزن
```

- المنفذ **ثابت** (`3105`) لأن أصل الواجهة يحدّد نطاق `localStorage`؛ عند انشغاله تُجرَّب
  `3106`, `3107`, `3102`, `3103` ثم منفذ يعيّنه النظام، ويُطبع تنبيه بذلك.
- يمكن تغيير الوجهة: `--api=http://127.0.0.1:3100` أو `LIFEOS_API_URL`،
  والمنفذ: `--port=3105` أو `LIFEOS_DESKTOP_PORT`.

## 3. الأمان (ما فُحص فعليًا)

- `contextIsolation: true` · `sandbox: true` · `nodeIntegration: false` — يتحقق منها الاختبار الآلي.
- منع: النوافذ المنبثقة، `webviewTag`، طلبات الأذونات (camera/mic/geolocation)، والتنقّل خارج
  أصل التطبيق (تُفتح الروابط الخارجية في المتصفح).
- CSP: للإنتاج `default-src 'self'` بلا `unsafe-inline`/`unsafe-eval`، وللتطوير نسخة أوسع تكفي Vite.
- IPC ضيق مع تحقق من النوع/الحجم في الطرف الرئيسي؛ لا تمرير لـ`ipcRenderer` نفسه إلى الواجهة.
- لا أسرار في الكود: بيانات التحقّق تُمرَّر عبر متغيرات بيئة وقت التشغيل فقط.
- رمز التحديث: `safeStorage` (DPAPI) + ملف في مجلد التطبيق، ويُخزَّن مشفَّرًا ببادئة `enc:`.
  عند تعذّر التشفير يعمل التطبيق ويُعلن الحالة عبر `getInfo().encryptionAvailable` بدل الادّعاء.

## 4. الملفات

| الملف | المسؤولية |
| --- | --- |
| `src/main.ts` | دورة حياة التطبيق، النافذة، القائمة، tray، IPC، وضع `--smoke`. |
| `src/preload.ts` | الجسر الضيق (contextBridge) بين الواجهة والطرف الرئيسي. |
| `src/app-server.ts` | خادم الملفات + SPA fallback + وكيل `/api` + CSP + حماية المسار. |
| `src/config.ts` | تحليل `argv`/بيئة التشغيل: الجذر، الـAPI، المنفذ، البروفايل، وضع التطوير. |
| `src/settings-store.ts` | إعدادات المستخدم (إشعارات، tray، أبعاد النافذة، سجل الإشعارات) بكتابة atomic. |
| `src/local-state.ts` | مخزن مفتاح/قيمة في مجلد التطبيق (رمز التحديث المشفَّر). |
| `src/notifications.ts` | اختيار الجلسات المستحقة، صياغة النص، منع التكرار. |
| `src/icon.ts` | توليد `icon.png` و`icon.ico` برمجيًا (CRC32 + zlib). |
| `src/verify.ts` | خطوات التحقّق الحقيقي التي ينفّذها `--smoke`. |
| `scripts/package.mjs` | حزم Windows بـ`@electron/packager` + تحقق بعد الحزم. |

## 5. وضع التحقّق (`--smoke`)

يشغّل التطبيق نفسه، ينتظر الواجهة، ينفّذ الخطوات، يطبع سطر `SMOKE_RESULT {...}` إلى stdout،
ويكتب ملف JSON/Lقطة عند تمرير `--shot=<path>` (مفيد لأن تطبيق واجهة رسومية على Windows لا
يملك طرفية مُتصلة).

```
& "apps\desktop\release\Personal Life OS-win32-x64\Personal Life OS.exe" `
  --smoke --profile-dir=C:\temp\lifeos-profile --shot=C:\temp\shot.png
```

- بيانات الدخول: `LIFEOS_E2E_EMAIL` و`LIFEOS_E2E_PASSWORD` (تُمرَّر في البيئة، لا تُكتب في ملف).
- `--profile-dir=<path>` يعزل التشغيل عن ملف المستخدم الحقيقي (موصى به دائمًا للتحقّق).
- المسارات التي تحتوي مسافات يجب تقييدها بعلامات اقتباس عند تمريرها من PowerShell.
- الخطوات: أمان النافذة، الرسم، الجسر، غياب `node` في الواجهة، الإشعارات (opt-in/مرة واحدة/فائتة/
  استعادة الإعداد)، ترويسة CSP، وصول الـAPI، تسجيل دخول فعلي، الرمز خارج `localStorage` ومشفَّر،
  لوحة اليوم، قابلية نداء الإشعارات، ثبات الجلسة بعد إعادة التحميل، صفر أخطاء طرفية، لقطة.

## 6. الحزم

- الناتج: `apps/desktop/release/Personal Life OS-win32-x64/` (مجلد قابل للتشغيل، بلا مثبِّت).
- لا توقيع ولا نشر (بقرار المستخدم): Windows SmartScreen قد يُظهر تحذيرًا — سلوك متوقع.
- أصول الويب تُنسخ إلى `resources/web` عبر `.stage/web`، ومعها تحقق بعد الحزم من
  `resources/web/index.html` لمنع حزمة ناقصة.
- `release/` و`.stage/` و`assets/` و`dist/` مستثناة من Git.

## 7. القيود المعروفة (مقصودة، لا تُخفى)

- لا تشغيل تلقائي للـAPI، ولا وضع بلا اتصال، ولا مزامنة خلفية: انقطاع الـAPI يظهر خطأً صريحًا.
- سجل الإشعارات يقتصر على 200 معرّفًا (الأقدم يُزاح)، فلا يتضخم الملف.
- وضع `--smoke` يكتب معرّفات جلسات اختبارية في **ملف التعريف المستخدم**؛ لذلك يُشغَّل بـ
  `--profile-dir` لملف معزول.
- `npm run lint` غير متاح (eslint غير مثبَّت في المستودع) — الفحص المتاح: `typecheck` + `vitest`
  + تشغيل فعلي.
