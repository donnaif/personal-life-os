# DEPLOYMENT — النشر والتشغيل

نسخة عامة قابلة للمشاركة. أي نشر على مضيف حقيقي (DNS، جدار حماية، وكيل عكسي) يحتاج قرارًا
وقاعدة عزل خاصة به ولا يُفترض ضمنًا.

## 1. بناء الإنتاج

```powershell
npm install
npm run typecheck
npx vitest run
npm run build:web        # → apps/web/dist
```

## 2. تشغيل الـAPI

```powershell
npm run dev:api                              # تطوير (tsx watch) على 127.0.0.1:3100
```
للإنتاج: شغّل `apps/api` كعملية Node طويلة العمر (يمكن استخدام PM2 أو أي مدير خدمات)
مع ملف `.env` يحدّد `JWT_SECRET` وقيمة منفذ/مسار قاعدة البيانات. القاعدة ملف SQLite واحد
(`apps/api/data/lifeos.sqlite`) — انسخه احتياطيًا قبل أي ترقية، فهو يحتوي كل البيانات.

**تنبيه:** ملف قاعدة البيانات والنسخ الاحتياطية **لا تُرفع إلى Git** (مستثناة في `.gitignore`).

## 3. خدمة الواجهة

`apps/web/dist` ملفات ثابتة: قدّمها بأي خادم ثابت (nginx، أو خادم Node بسيط) مع توجيه
`/api` إلى الـAPI بنفس أسلوب وكيل التطوير — **إزالة بادئة `/api`** مطلوبة
(`/api/tasks` → `/tasks`). هذا شرط تشغيل، وتطبيق سطح المكتب يقلّده في `src/app-server.ts`.

## 4. حزم تطبيق سطح المكتب

```powershell
npm run build:web
npm run package:win      # → apps/desktop/release/Personal Life OS-win32-x64/
```
الناتج مجلد قابل للتشغيل (بلا مثبِّت). التوزيع لبقية الأجهزة = نسخ المجلد. لا توقيع رقمي،
لذلك قد يُظهر Windows تحذير SmartScreen.

## 5. قائمة تحقق قبل النشر

- [ ] `JWT_SECRET` قيمة عشوائية جديدة (لا القيمة الافتراضية).
- [ ] `.env` غير مُتتبَّع في Git.
- [ ] `npm audit` بلا ثغرات معروفة.
- [ ] `npm run typecheck` + `npx vitest run` نظيفان.
- [ ] الـAPI يعمل، و`/health` يرد `200`.
- [ ] الواجهة تصل للـAPI (لا أخطاء CORS/شبكة في الطرفية).
- [ ] نسخة احتياطية من `lifeos.sqlite` مأخوذة قبل الترقية.
- [ ] الخدمات الأخرى على المضيف لم تُلمس (إن كان المضيف مشتركًا).
