# TESTING STRATEGY — استراتيجية الاختبارات

## 1. المستويات

1. **وحدة (Vitest):** منطق المجال في `packages/core` — الجدولة، التكرار، الجلسات، المؤقت،
   اكتشاف التعارض، إعادة الجدولة، حسابات التقارير، منطق المزامنة.
2. **تكامل:** API ↔ SQLite — CRUD، الترحيلات، المزامنة، الصلاحيات، معالجة الأخطاء.
3. **واجهات:** مسارات المستخدم عبر Playwright MCP (إضافة مهمة، بدء جلسة، إكمال، تقارير، RTL).
4. **منصات:** Windows (Electron) لاحقًا؛ Android (APK على محاكي/جهاز) لاحقًا بقدر المتاح.

## 2. قواعد

- لا يُعتبر أي جزء مكتملًا دون اختبارات نُفذت فعلًا ونتائج مسجلة.
- اختبار حالات الفشل لا المسار المثالي فقط.
- ممنوع بيانات وهمية في الواجهة النهائية.
- اختبارات المؤقت تعتمد على **وقت مرجعي قابل للحقن (injected clock)** لا على `Date.now()` الحقيقي.
- المناطق الزمنية: اختبارات صريحة لسيناريوهات تغيّر التوقيت.

## 3. أوامر

```powershell
npm test          # كل اختبارات الوحدة
npm run typecheck # فحص الأنواع
```

## 4. تعريف النجاح

- لا أخطاء بناء غير معالجة.
- لا اختبارات فاشلة غير موثقة.
- العمليات الأساسية تعمل من الواجهة حتى قاعدة البيانات.
- نتائج الاختبارات في `PROJECT_STATUS.md` تعكس ما نُفِّذ فعلًا.
